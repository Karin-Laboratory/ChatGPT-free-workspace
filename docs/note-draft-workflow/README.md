# note記事を下書きにする手順

AIがnoteの記事を新規作成し、関連記事を標準埋め込みカードにして、公開せず下書き保存するための再利用手順です。公開操作は明示的に依頼された場合だけ行います。

## 依頼時に受け取る情報

- 採用するタイトルと原稿、または記事のテーマ
- 関連記事を指定する場合は3本のURL（未指定なら著者の記事一覧から候補を選び、タイトルとURLを照合）
- 画像やタグが必要な場合は、その希望と条件

## 作業手順

1. **対象と原稿を確定する**
   - ユーザーが採用した最新版を使う。見出し、段落、強調、関連記事の位置、締めの一文を整える。
   - 他の記事や未保存の編集を上書きしない。新規投稿なら新しいエディタを開く。
   - 関連記事は記事ページでタイトルと正確なURLを照合する。既に正しい埋め込みがある記事は重複追加しない。

2. **noteの編集画面へ入力する**
   - ログイン済みのWork内蔵ブラウザーを使う。TinyFishなど別のブラウザー操作基盤は使わない。
   - 記事タイトル欄と本文欄を画面で識別する。
   - 本文は段落・見出しを保って入力する。HTMLを貼る場合はクリップボード経由でエディターに貼り付け、画面上で見出しと段落として取り込まれたことを確認する。
   - DOMの直接書き換えや内部API呼び出しで入力を代替しない。

3. **関連記事を標準埋め込みカードにする**
   - 記事末尾または指定位置に、1本ごとに独立した空段落を作る。
   - URLを1本だけ貼り付け、Enterを押してカード化を待つ。
   - カード表示が確定してから次のURLへ進む。表示が遅いときに同じURLを再入力しない。
   - 3本すべてについて画面表示とリンク先を確認する。通常のハイパーリンクは埋め込みカードの代用にしない。

4. **カバー画像・タグ（依頼がある場合）**
   - 画像は記事内容に合うものを用意し、noteの画像要件を画面で確認してからカバーに設定する。
   - タグは主題と読者に合う候補を設定し、画面で個数と内容を確認する。
   - タグを保存するために一時公開する手順は、公開露出が発生し得るため、ユーザーがその影響を理解した明示的な指示なしに行わない。下書き保存でタグが保持されない場合は公開せず状況を報告する。

5. **下書き保存と確認**
   - 「下書き保存」を使い、「保存済み」等の完了表示を確認する。
   - 最終画面でタイトル、本文末尾、関連記事カードの数・内容、カバー、タグ（依頼時）を確認する。
   - 下書き依頼では「公開に進む」や「投稿する」を押さない。
   - 編集URLと、保存できた項目をユーザーへ報告する。

## 操作上の注意

- 以前のタブID、DOM要素ID、画面座標は再利用せず、作業ごとに現在の画面を確認する。
- 複数画面編集の確認が出たら、本文量や更新時刻を比較し、今回の編集がある画面を選ぶ。
- カード生成や文字数表示には遅延がある。画面を再確認してから次の操作を行う。
- 公開状態の変更は、下書き保存と別の操作として扱う。公開後に下書きへ戻せるか確認できていない画面では公開しない。

## 関連記事カードの例

以下は例です。実行時には各記事の現在のタイトルとURLを照合してください。

- https://note.com/deft_llama956/n/n75cefc59a51d
- https://note.com/deft_llama956/n/nbf0016ecb69e

## 再利用できる依頼例

「この手順に沿って原稿をnoteの新規下書きに整えて保存して。関連記事3本はnote標準の埋め込みカードにして。公開はしないで、編集URLを返して。」
