# AIで「私と気の合いそうな人」を見つけてフォローする

**note × AIブラウザー操作・実践Runbook（2026-11-02）**

カリンちゃんの実践から整理した、**共通の興味を持つnoteクリエイターをAIに見つけてもらい、本人アカウントで節度を持ってフォローする**手順です。SEO、無差別フォロー、フォローバック強要、フォロワー数の水増しを目的にしません。

> **重要**: この文書は操作手順の共有です。noteやChatGPTのUI、ログイン状態、利用規約、機能提供状況が変わるため、完全自動で必ず成功するという保証はありません。相手のページと現在のボタン表示を確認できない場合は実行しません。

## 何を再現するか

1. 自分のnote記事・プロフィールから、読者に届けたい主題を抽出
2. note内で、近いテーマの**実在する書き手**を個別に探す
3. プロフィールと最近の記事を読み、「なぜ関心が合うか」を説明
4. フォロー済み・重複・広告的アカウントなどを除く
5. ログイン済みの本人用ブラウザーで、少人数だけフォロー
6. **「フォロー中」等の事後表示を1件ずつ確認**し、結果を記録
7. 警告・アクセス制限・不自然な画面変化があれば直ちに停止

ユーザー自身の例では、AI個人開発、初心者向けAI活用、ものづくり、OpenWrt、ホームラボ等を関連テーマとしました。これは個人用の例であり、再利用する際はあなたの興味と実際の記事内容に置き換えてください。

## 確認済みの実践記録と限界

- 2026-11-02、少人数の候補選定 → フォロー → **各人の「フォロー中」を確認**する流れに成功したと報告されています。
- Workの認証済み内蔵ブラウザーで追加3件のフォローが完了した記録があります。さらに20件の追加実施・確認を報告した記録があります。
- 初期の別実行では5件のフォローと事後確認が完了した記録があります。
- その後「スキをくれた人を全員フォロー」は、note側の安全制限の可能性があり、**途中で停止**しました。大量フォローや制限回避を手順化しません。
- 同日、noteの28日集計でフォロワー増加が63人から73人になったことが観測されています。ただし、**増加のすべてをAIフォローの効果と断定できません**。
- 別の定期自動実行では、認証済みブラウザーに到達できず、**実フォロー0件**だった記録があります。スケジュールを作るだけではブラウザー操作は成立しません。

以上は過去の作業報告に基づく整理です。プロフィールの全URL、全操作ログ、ブラウザー内部状態の完全な実証セットではありません。サイト側の現在の実装と権限は、再実行時に確認してください。

## 必要なもの

- あなた自身のnoteアカウントと、自分でログイン済みのブラウザーセッション
- ページを**閲覧だけでなくクリック操作できる**AIブラウザー機能（例: 利用可能なChatGPT Workのブラウザー操作）
- 関連する自分の記事URLまたはテーマの説明
- フォローの実行許可。AIに一任したくない場合は候補一覧までで停止可能
- 結果記録先。公開GitHubには私的なセッション情報やログイン情報を書かない

**通常のチャットでブラウザーのタブを読めても、クリックできるとは限りません。** 操作権限がない環境では候補リストだけ作り、完了したと報告しないこと。

## 最短の使い方

1. [AGENT_PROMPT.md](AGENT_PROMPT.md) のひな形をAIに渡し、自分の記事URL・関心テーマ・上限人数を書き込む。
2. AIが候補を提示。フォローを許可するか決める。
3. 許可済みの範囲でAIが1人ずつ操作し、毎回成功表示を検証する。
4. [RUNBOOK.md](RUNBOOK.md) の形式で「成功・既フォロー・未実行・不明」を分けて記録する。

**少人数ずつ、人間の関心に沿ったフォロー**が原則です。速度や一日当たり人数の上限を「これなら安全」と断言することはできません。サイトの警告・規約・操作制限が最優先です。

## 読者向けの考え方

目的は「AIにフォロワーを稼がせる」ことではなく、**自分が読みたい書き手と出会うこと**です。フォローバックの有無を選定評価に使わず、いいね・コメント・DMの自動送信を付随させません。

公開時の注意: ほかの人のアカウントや作品を調べる場合、公開情報だけ扱い、過度な収集・人物属性の推定・リストの大量公開を避けてください。認証トークン、Cookie、スクリーンショットに写り込む非公開情報は保管・公開しないでください。
